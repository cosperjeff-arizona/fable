# M3 — History driver + CLI (implementation spec)

Depends on M1 (phonology/lexicon) and M2 (sound-change engine). Deliverables: the simulation
driver that grows a family tree and evolves the lexicon along it, a versioned JSON dump of a
complete simulation (the contract for M4's explorer), and a small hand-rolled CLI.

## `src/history.ts` — the driver

```ts
type SimConfig = {
  seed: number;
  centuries: number;        // default 20
  maxLeaves: number;        // default 6
  splitChance: number;      // default 0.18 per century per living branch (while under maxLeaves)
  changeChance: number;     // default 0.45 per century per branch
};

type ChangeEvent = { century: number; change: AppliedChange };
// AppliedChange = the *instantiated* rule data: { catalogId, description, subRules }.
// It must be JSON-serializable and replayable without re-sampling — factories sample
// variants (e.g. which chain shift), so the event stores the resolved subRules, not the id alone.

type Branch = {
  id: string;               // 'root', 'root.0', 'root.0.1', …
  start: number; end: number;
  events: ChangeEvent[];
  paradigmNotes: { century: number; affixRole: string; note: string }[];
  children: Branch[];
  name?: string;            // leaves only; see naming
};

type Simulation = {
  config: SimConfig;
  inventory: Inventory;     // proto inventory
  lexicon: SerializedLexicon;
  familyName: string;
  root: Branch;
};
```

Driver semantics, per century, per living branch (deterministic iteration order: depth-first,
children in creation order):

1. With `changeChance`, call M2's `sampleChange` using the branch's **own named stream**
   (`branch:<id>` from `makeStreams`) and the branch's current `LangState`. A branch's state
   = proto lexicon evolved through the concatenated events of its ancestor path (cache it —
   don't re-evolve from scratch each century; keep the working lexicon per living branch).
2. With `splitChance` (only if current leaf count < maxLeaves and century ≤ centuries − 3),
   the branch stops and two children begin; children inherit nothing but the path (their
   streams differ, so histories diverge immediately).
3. After an applied change, run M2's paradigm-collapse detection; append any new collapse
   notes.

Guarantee at least one event on every branch whose span is ≥ 2 centuries (force-sample at the
midpoint if none landed) — zero-change branches make boring, indistinguishable daughters.

## Naming

- Leaf names: the branch's evolved word for `people`, romanized, capitalized. Duplicates get
  directional prefixes North/South/East/West in tree order (port the prototype's logic).
- Family name: `Proto-` + capitalized romanization of the proto word for `tongue`.

## `src/query.ts`

Pure functions over a `Simulation`:

- `leaves(sim): Branch[]`, `pathTo(sim, branchId): Branch[]`
- `formIn(sim, conceptId, branchId): Word` — proto root evolved through the path's events.
- `trace(sim, conceptId, branchId): TraceStep[]` — replay recording only form-altering steps
  (reuses M2's `evolve`; must reproduce the simulation exactly).
- `cognates(sim, conceptId): { branchId, name, form }[]` — one row per leaf.

## JSON dump (`src/serialize.ts`)

`toJSON(sim): EtymonDumpV1` and `fromJSON` round-trip. Shape: `{ formatVersion: 1, ...Simulation }`
with `Map`s flattened to records and every `Word` carried as **both** structured segments and
its romanization (the explorer should not need to reimplement `romanize`). Round-trip test:
`toJSON(fromJSON(toJSON(sim)))` deep-equals `toJSON(sim)`.

## `src/cli.ts` (`etymon` bin)

Hand-rolled argv parsing, zero deps. Commands:

```
etymon generate --seed 42 [--centuries 20] [--max-leaves 6] [--json dump.json]
    prints: family header, tree (ASCII, with year spans), per-branch change history
etymon dict <language> --seed 42        full dictionary of one leaf (concept, form, notes)
etymon trace <concept> --seed 42 [--lang <name>]   etymology per leaf (or one leaf)
etymon cognates <concept> --seed 42     cognate row across all leaves
etymon tree --seed 42                   just the tree
```

Every command re-runs the simulation from the seed (fast, deterministic) unless `--from
dump.json` is given. Output style: follow the prototype's report (`prototype/etymon.mjs`) —
it's the look we want, including `*` before proto forms and `>` derivation chains.

## Acceptance criteria

1. Golden snapshot of `etymon generate --seed 42` (and seeds 1, 2026) full text output.
2. Trace-fidelity property test (≥10 seeds): for every leaf × 20 sampled concepts,
   `trace(...)` final form === `formIn(...)` === the form shown in cognate tables.
3. JSON round-trip test; dump for seed 42 committed under `examples/seed42.json`.
4. Language names unique per simulation (property test over ≥25 seeds).
5. Every branch with span ≥ 2 centuries has ≥ 1 event (property test).
6. Full 20-century, 6-leaf simulation completes in < 2 s.
7. Stream discipline: simulating with `maxLeaves: 2` vs `6` yields identical root-branch
   event logs for the same seed (branch streams are independent; the tree shape must not
   reshuffle sibling histories).
