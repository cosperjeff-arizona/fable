# M4 — Explorer-lite (implementation spec)

A static, fully self-contained HTML explorer for one simulation. Depends on M3. Deliverables:
an additive `derived` section in the JSON dump, an `explore` CLI command that emits a single
HTML file with the dump embedded, and the explorer UI itself.

## Guiding decision

The explorer must NOT reimplement the sound-change engine (or romanize, or anything). The
dump gains a `derived` section computed by the real engine at dump time; the explorer is pure
display. This keeps the HTML small in code, honest in content, and immune to drift between
engine and UI.

## Dump extension (`src/serialize.ts`, additive — formatVersion stays 1)

```ts
type DerivedLeaf = {
  branchId: string;
  name: string;
  dictionary: {
    concept: string;
    romanized: string;                      // final form in this leaf
    trace: { century: number; romanized: string; description: string }[]; // form-altering steps only
  }[];
};
type EtymonDumpV1 = Simulation & { formatVersion: 1; derived?: { leaves: DerivedLeaf[] } };
```

- `toJSON(sim, { derived: true })` computes it via src/query.ts (`formIn`/`trace`) for every
  concept x leaf. `fromJSON` passes it through untouched (still optional).
- `generate --json` now always includes `derived`. Acceptance: a test recomputes 20 random
  (concept, leaf) pairs with `formIn`/`trace` and asserts they match the derived section.
- Regenerate `examples/seed42.json` with the derived section (the M3 test comparing it to a
  fresh simulation must be updated to pass `{ derived: true }` too).

## CLI (`src/cli.ts`)

```
etymon explore --seed 42 [--centuries N] [--max-leaves N] [--out explorer.html]
```

Default `--out`: `etymon-explorer.html`. Implementation: the HTML template lives in
`src/explorer/template.ts` as an exported string (a `.ts` string module, not a separate
`.html` file, so `tsc` handles it and dist needs no asset copying). The command replaces the
single placeholder `"__ETYMON_DUMP_JSON__"` with the JSON of the dump (JSON-escape `</script`
sequences: replace `</` with `<\/` in the embedded JSON string) and writes the file.

## Explorer UI (`src/explorer/template.ts`)

Single HTML document, inline CSS + vanilla JS only. Hard requirements:

- **Self-contained**: zero external requests — no CDNs, fonts, images, fetch. (Test greps the
  emitted file for `http://`, `https://`, `fetch(`, `import(` — none may appear; an `xmlns`
  attribute is the only allowed exception.)
- **Theme-aware**: respects `prefers-color-scheme` for light/dark; readable in both.
- **No build step**: hand-written modern JS (ES2020), no frameworks.

Layout (desktop: two columns; narrow: stacked):

1. **Header** — family name, seed, daughter count, years simulated.
2. **Tree panel** — the family tree as a nested indented list (CSS, no SVG needed). Each leaf
   is clickable; intermediate nodes show split year. Selected leaf is highlighted. Below the
   tree, the selected branch's sound-change history (year + description, from the events of
   the path, oldest first) and paradigm-collapse notes.
3. **Dictionary panel** — for the selected leaf: a filter input (substring match on concept
   or word) over all ~200 entries, rendered as rows `concept — word`. Clicking a row opens:
4. **Etymology view** — the trace as a vertical timeline: proto form `*word` at top, one node
   per step (year, new form, change description), final form emphasized at bottom. A
   "▶ play" button reveals steps one-by-one (~600 ms apart); instant-render otherwise. Also
   show the word's cognate row: every leaf's form for that concept in a small table, with the
   selected leaf highlighted, so relatedness across the family is visible from any word.

Empty states: if the dump lacks `derived`, show a single message ("regenerate this dump with
a newer etymon: etymon generate --json ...") instead of broken panels. A drag-and-dropped
`.json` file onto the page replaces the current dump (read via FileReader; same validation).

## Acceptance criteria

1. All existing tests stay green; `examples/seed42.json` regenerated with `derived` and its
   fidelity test updated.
2. Derived-section fidelity test (described above).
3. `explore` emits one file; tests assert: parses as text, contains the embedded JSON (parse
   it back out and compare `familyName`), passes the self-containment grep, and contains no
   `"__ETYMON_DUMP_JSON__"` placeholder remnant.
4. Escaping test: a dump whose strings contain `</script>`-hostile content (craft one in the
   test by hand) still embeds safely.
5. Manual visual review by the project lead after commit (leave the emitted
   `etymon-explorer.html` OUT of git; add it to .gitignore).
